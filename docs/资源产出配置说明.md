# 资源产出配置说明

唯一数值入口是 [`assets/scripts/core/EconomyConfig.ts`](../assets/scripts/core/EconomyConfig.ts)，编辑顶部 `settings` 中的数值即可。文件内有中文注释；底部负责校验并冻结配置，通常不需要修改。

修改后需要重新构建游戏才会生效。它是随游戏打包的 TypeScript 配置，不是运行时从服务器获取的热更新表。当前挑战和独立 BOSS 的首关、矿山及七天签到的钻石产出基数为原版 2 倍。挑战与 BOSS 按各自关数线性递增：每提高一关，普通奖励和广告额外奖励各增加首关金额的 10%，不复利；界面和到账共用同一关数计算结果。兑换码仍为 2000 钻，新手补足值为 200 钻，测试补给仍为 200 万钻；钻石消费价格不变。

## 配置分组

| 分组 | 可以调整的内容 |
| --- | --- |
| `newGame` | 新档金币、钻石、星石、紫币、宠物币和初始装备；金币/紫币用字符串，支持科学计数法 |
| `onboarding` | 首次打开武器面板的钻石补足值，默认补到 200；只补差额且只执行一次 |
| `gold` | 主线树木基础金币、逐关增长、树木档次/主线 Boss 倍率，以及金币升级、永久金币强化、皮肤和宠物的金币加成 |
| `speedRun` | 普通挑战首关 60 + 180 钻，总计 240；`stageGrowthPercent: 10`，此后每关普通 +6、广告额外 +18 |
| `boss` | 独立 BOSS 首关 300 + 600 钻，总计 900；`stageGrowthPercent: 10`，此后每关普通 +30、广告额外 +60 |
| `dailyCheck` | 七天钻石最终奖励 `[140, 400, 800, 1200, 1600, 2000, 3000]`，共 9140；每日上限仅支持 0（暂停）或 1 |
| `mine` | 矿山每日次数、普通/钻石矿积分、积分兑换钻石比例、钻石矿数量、结算广告追加倍率及攻速广告时长/倍率 |
| `offline` | 离线最低时长、基础时长上限、清关耗时系数与固定耗时、原版永久增益兼容倍率；金币基础和金币加成共用 `gold` |
| `rebirth` | 紫币产出公式参数、最低产出关卡、收益百分比、广告最终倍率和每日次数，默认广告最终 3 倍、每日 1 次 |
| `raid` | 每日免费/广告入场次数、分层星石奖励、周任务条件和奖励 |
| `weapons` | 抽取钻石价格、D/C/B/A 品质概率、每日广告武器品质与领取次数、限时广告武器 ID/有效秒数/发放条件 |
| `hunt` | 每小关宠物币奖励、结算广告额外倍率，默认每关 30，广告追加本次累计的 1 倍 |
| `pets` | 普通抽取价格和产出品质；钻石和宠物币两种抽取共用价格；每日广告宠物品质与次数，默认 C 阶、1 次 |
| `fish` | 钻石抽鱼价格、每日总免费次数、其中免广告次数、免费/钻石基础品质和四档抽取概率 |
| `adventure` | 旅行时长、经验公式与上限、初始票券和核心、补票周期与上限、每小时核心/经验、品质收益、广告每日次数与缩短分钟数 |
| `relics` | 每抽核心价格、升级碎片消耗、能力上限、四模式候选池、原包三份300项成长表及各类成长数值 |
| `redeemCodes` | 兑换码及其钻石奖励；每个码每份存档限领一次，可添加多条 |
| `testResources` | 测试钻石、星石、旅行票券和各类核心补足值、旅行能力单次最大抽取数、金币/紫币按剩余升级预算补给的开关、测试转生奖励兜底关卡 |

狩猎每清一小关即时发宠物币，进度和钱包在同一次 v3 保存中提交。失败、放弃不回收已发奖励；广告成功只追加本次累计一次。首次狩猎通关后可满足每日广告宠物条件，仍须打开广告开关，满包、取消或失败不消耗次数。详见[狩猎说明](狩猎说明.md)。矿山的收益和次数见[矿山说明](矿山说明.md)。离线结算和弹窗见[离线收益说明](离线收益说明.md)。七天钻石为原版逐日奖励的两倍最终值，界面和领取共用 `dailyCheck`，不再次乘二；领取与存档规则见[七日领取说明](七日领取说明.md)。

## 挑战与 BOSS 的关数奖励

以各自界面显示的第 N 关为准（内部 stage = N−1），普通奖励与广告额外奖励分别按 `floor(首关金额 × [1 + stage × stageGrowthPercent / 100])` 计算，最后分别取整后相加。默认增长 10% 是增加首关金额，不是每关乘 1.1；两种玩法独立读取自己的进度，不读取主线关数。

| 关数 | 挑战普通 / 含广告合计 | BOSS 普通 / 含广告合计 |
| --- | --- | --- |
| 1 | 60 / 240 | 300 / 900 |
| 2 | 66 / 264 | 330 / 990 |
| 10 | 114 / 456 | 570 / 1710 |
| 11 | 120 / 480 | 600 / 1800 |

胜利推进下一关后，结果页、退出动画和广告追加仍使用本次已完成关数；回到准备页才预览下一关。失败和主动退出不增加奖励或关数。旧档的关数和余额直接保留，新公式从下一次挑战开始使用，不重算历史收益。计算使用十进制运算避免浮点误差；极端关数的金额超出安全整数钱包范围时保留存档并禁止入场。

## 常见修改

普通挑战每关固定给 50 钻、看广告后总共获得 200 钻（关闭关数递增）：

```ts
speedRun: { baseDiamonds: 50, additionalDiamonds: 150, stageGrowthPercent: 0 },
```

`additionalDiamonds` 是额外追加值。基础奖励在胜利时入账，广告成功后追加；广告取消或失败不追加，重复回调不重复发放。界面会显示 50 / 200。

强化转生想改为最终 5 倍、每天 2 次，调整 `rebirth.adTotalMultiplier: 5`、`rebirth.adDailyLimit: 2`。这里的倍率是最终总奖励，不需要另外加上普通转生奖励。每日次数可以设为 0；广告是否可用仍由 `ContentConfig.ts` 中的广告总开关和广告位开关控制。

矿山默认配置如下；例如将 `scorePerDiamond` 改为 20，结算、战中预览和矿石钻石飘字都会一起按 20 积分兑换 1 钻计算。`adAdditionalMultiplier` 是追加倍数，填写 3 表示合计 4 倍。

```ts
mine: {
  freeEntriesPerDay: 2,
  normalScore: 2, rareScore: 20, scorePerDiamond: 10,
  rareOreCount: 100, adAdditionalMultiplier: 3,
  speedBuffSeconds: 300, speedBuffMaxSeconds: 900, speedBuffMultiplier: 3,
},
```

普通抽武器想设为 80 钻、80% D 和 20% C，调整 `weapons.drawPrice: 80`、`drawGradePercents: [80, 20, 0, 0]`。四项必须是非负整数且总和为 100，同品质内等概率。价格、概率说明和发放读取同一份配置。若改变价格，按需要同时调整 `onboarding.firstDrawDiamondFloor`，确保首次补给足够完成教学要求的两次抽取。

新手教学在攻击升级达到 Lv.3、挑战与武器同时解锁后开始武器操作，无需挑战首胜。首次打开面板补足 200 钻，连续两次抽取各消耗 100 钻，均从现有 D 级武器池选型号；随后两把 D 级材料固定合成 ID 3「C级山羊弩」，基础攻击 240，穿戴到任一合法装备槽结束教学。教学的抽取次数、品质和固定合成 ID 集中在 `session/ContentConfig.ts` 的 `WEAPON_TUTORIAL_RULES`；战斗攻击值继续来自武器目录，正常抽取概率和教学外合成随机规则保持原样。

武器品质从 0=D、1=C 到 12=ZZZ；宠物品质从 0=D 到 9=ZZZ，名称以各自目录为准。武器 ID 参见 `core/WeaponData.ts`。每日武器每次领取一把；限时武器每份存档仍只触发一次首次合成优惠，配置的是未来新出现的优惠。

鱼的品质下标为 0～12，鱼缸固定容纳 20 条。`fish.drawPrice` 默认 200 钻；`freeDrawsPerDay: 5` 与 `noAdDrawsPerDay: 3` 表示前三次直接免费，后两次须广告成功。取消、失败和重复广告回调不增加鱼、不消耗次数。免费抽取从 `freeBaseGrade: 0` 起，钻石抽取从 `premiumBaseGrade: 1` 起，再按 `drawGradePercents: [60, 30, 10, 0]` 选择偏移 0、1、2、3；该概率取自原版实际场景序列化值，覆盖原构造函数默认值。调整概率须四项非负整数且合计 100，基础品质最高为 9。合成仅消耗两条同品质鱼并生成下一品质，放生没有资源返还。

## 计算与存档

- 测试环境旅行票券由 `testResources.adventureTickets` 补至 1000000，四类核心分别由 `testResources.adventureCores` 补至 1000000。新档、旧档启动恢复完成后及手动“补资源”都会补足差额，已有更高余额不回收；测试覆写可以设为 0 以关闭对应补给。旅行等级、经验、已派遣行程、宠物锁及广告次数保持原样，普通环境仍使用 `adventure.initialTickets/initialCores`。
- 测试环境旅行能力“最大抽取”每次最多购买 `testResources.relicMaxDrawCount` 个，默认 100；界面购买数量、显示价格、实际抽取及核心扣款使用同一上限，余额不足时按实际可购买数量计算。该值必须为正安全整数；正式环境保留按全部可用核心抽取的行为。补给数量必须为非负安全整数。
- 旅行测试补给在离线恢复结算成功后执行；损坏的旅行块不被补给重建，原块随档保留。存档写入状态不确定或已有待提交结算时不补给旅行钱包，以免覆盖尚未确认的消费或奖励。
- 七天钻石按当前项目的本地自然日判定，每天依次领取一格；中断不会清零或补领跳过天数。第七格领完当天全部保持已领取，次日从第一格重新循环。首日和缺少签到块的旧档从第一格可领开始；不迁入原版联网校时或收益审计系统。
- 签到 `dailyCheck.lastClaimDay/checkNum/totalCheckNum` 与钻石钱包在同一份 v3 存档中写入并读回确认，成功后才更新内存及界面。失败可重试；无法确认的写入阻止旧内存自动覆盖，重启后从存档恢复。损坏的签到块原样保留并禁止领取，不清空余额或其他玩法。日期回拨不恢复领取资格。
- `dailyCheck.diamondsByDay` 必须保留七项顺序，值为非负安全整数；零奖励也记录当天领取。修改奖励不追溯补发已领日期；`dailyLimit` 从 1 改为 0 暂停领取、改回 1 恢复原有进度，不接受大于 1 的值。
- 离线只在重启读档时结算，最低 30 秒、基础上限 28800 秒；后台恢复只更新存档时间。自动刷金币并用已有余额购买三项最低等级升级，同级顺序为攻击、攻速、金币。金币净差额可能为负数，它仅是摘要，不能再次发放。
- 离线金币使用 `gold` 的关卡基数、档次倍率和永久加成；完整清关耗时为战斗估算耗时 × `offline.clearTimeScale` + `offline.stageClearDelaySeconds`，默认 1.3 和 5 秒。`offline.permanentBuffMultiplier` 默认兼容原版 4 倍，但当前无付费增益状态，实际按 1 倍。能力攻击、金币、暴伤和额外离线时长参与计算；移动速度、跳关、装备位星级与矿山临时攻速不参与离线计算。
- 离线结果的金币、升级、进度和 `offline.lastSavedAtMs` 在同一份 v3 存档中提交并读回确认，成功后才启动战斗。保存失败重试同一候选结果；展示失败只重试资源，不再计算。旧档缺时间或时间非法/回拨时只初始化时间，不补发未知时段。前台每 10 秒保存，切后台立即保存。
- 矿山默认每天 2 次，普通矿 2 积分、钻石矿 20 积分，每 10 积分兑换 1 钻，对应单矿预览 0.2 / 2 钻；只在整局结算时向下取整。战中预览保留一位小数，不能逐矿向下取整。例如 9 个普通矿和 1 个钻石矿累计 38 积分，预览 3.8 钻，基础结算 3 钻，广告追加 9 钻，合计 12 钻。默认每局最多 100 个钻石矿，总矿数最多 1000；结算广告追加基础奖励的 3 倍，合计 4 倍。
- 矿山广告攻速默认 3 倍，每次增加 300 秒、上限 900 秒，退出矿山后继续生效。保存剩余前台时间，离线不扣时；倍率加入最终攻速间隔夹取前。两类矿山广告均受总开关和各广告位开关控制，正式默认关闭。
- 矿山扣票和结果奖励先验证整份存档写入，再更新界面与钱包；失败可重试，不重复发奖。旧档缺矿山块时初始化当天 0 次已用，原余额不变。调整每日上限不会清空已用次数，降低上限后剩余次数最低为 0。
- 金币与紫币保留原版大数精度、有效位截断和运算顺序。显示数值存在原本的取整/截断，不能简单把所有公式用普通浮点数代替。
- `gold.upgradeGrowthG17` 保留为字符串，默认 `1.0800000000000001`。它只影响金币获取升级；攻击成长仍使用战斗数值。`gold.rebirthUpgradeGrowth`、皮肤和宠物金币加成也独立于攻击/移动速度。
- 普通环境已有余额不因修改配置自动补差或回收；新档资源仅在创建新状态时使用。已有模块的正常存档优先恢复其余额；测试环境旅行补给按上述配置补足下限。
- 首次打开武器面板只将不足 200 钻的余额补到 200；已有余额达到或超过 200 时不增加。新档教学余额按 200 → 100 → 0 变化；若玩家先获得挑战首关的 60 钻奖励，则面板仅补差 140 钻。首次补给标记保存，重开、刷新和转生不会重领；不为此前 100 钻教学存档追加迁移或补偿，验收使用新档或教学复演。矿山旧历史最高也不按新基数重算。
- 教学成功抽取次数及合成、穿戴步骤与武器和钱包在同一份存档中提交。失败抽取、错误拖放和被教学限制的操作不推进；第一抽、第二抽、合成后刷新或重开面板均继续当前步骤，穿戴指定 C 级弩后才完成教学。
- 每日枪、强化转生、Raid 广告已使用次数随档保存。旧档的“当天已领取”迁移为已使用 1 次。提高上限后可继续领取剩余次数，降低上限不清空旧档；跨天按原来的日期规则刷新。
- 鱼的已领取日期和当天次数独立存档；降低每日上限仍保留已使用次数，日期回拨不会重新赠送免费次数。未包含鱼模块的旧档从空鱼缸开始，不重算已有余额或其他模块。
- 已经出现的限时广告枪按存档中的武器和到期时间继续兑现；修改配置只影响未来新优惠。
- Raid 周任务记录按下标保存。可以修改既有任务的目标和奖励，但已完成/已领取状态保留；不要直接重排、删除或新增任务，需要同步迁移存档和界面槽位。兑换码改奖励也不会重置原有已领取记录。
- 内容解锁门槛仍在 `session/ContentConfig.ts`。转生、皮肤和每日签到入口须同时满足教学完成、成功通关挑战次数达到 `rebirthSkinChallengeWins`（默认 1）；签到自动弹窗也遵循同一条件，达成后等待其他面板和场景过渡结束再显示。挑战失败或中途退出不计入，已有挑战首胜存档直接满足，刷新和转生保留。入口显示后，转生仍需满足原有第 3 关门槛；测试环境保留进度绕过开关。例如调整转生最低产出关卡，还需按设计核对入口及执行解锁关卡，避免玩家能转生但没有奖励。

后续新增产出遵循 [项目维护约定](../AGENTS.md)：配置存数值，玩法模块处理流程，钱包处理到账，界面展示相同数据，不在广告回调或 UI 中写第二份奖励常量。
