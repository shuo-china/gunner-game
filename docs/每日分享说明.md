# 每日分享

主页面右侧功能栏顶部增加分享入口。复用现有橙金底板与“分享”文字，主体是一枚由内置 imagegen 生成的蓝钻与金色分享箭头组合图标，延续现有深棕描边和块面风格。入口不显示奖励数字。图片保存为 `assets/resources/art/share-system/images/entry-share.png`，保留透明通道，生成提示词见 [分享图标生成提示词](./分享图标生成提示词.txt)。

## 玩家流程

- 点击入口，调起微信分享；本次分享经历后台并返回游戏后，等待云存档协调，再向服务器领取奖励。
- 默认奖励 80 钻，每个账号、存档命名空间每天一次；到账后隐藏，服务器北京时间次日零点恢复资格。
- 微信接口无法可靠确认消息是否发送，因此取消后返回也可能获奖，这是本功能采用的产品规则。不会把停留时间作为成功依据。
- 调起异常或 30 秒内没有进入后台时结束本次操作，不占奖励次数；进入后台后没有分享时长限制。
- 领取失败但尚未确定结果时，不重复调起分享。已经持久化的请求沿用原编号恢复；存档同步阻断时沿用现有重新进入流程。跨日尚未结算的同一笔操作按服务器首次结算日计数。
- 与每日签到共用开放条件：完成教学且成功通关至少一次挑战后，才在主页面显示。可见性与点击资格直接读取签到内容状态，不另设一套门槛；分享当天领取后仍隐藏。弹窗、非主模式及其他暂停状态下不可操作。其他未接入分享的平台隐藏入口。

## 配置与扩展

微信小游戏创建分享适配器时，注册 `wx.onShareAppMessage`、`wx.onShareTimeline` 并调用 `wx.showShareMenu({ menus: ['shareAppMessage', 'shareTimeline'] })`，启用右上角“转发给朋友”和“分享到朋友圈”。返回前台时重新启用菜单，不重复注册回调；销毁时只移除当前适配器自己的监听。菜单标题统一为「三只小狐狸，能闯到第几关？」，接入审核素材前仍使用微信默认卡片图片，与教学/挑战解锁及每日奖励资格无关；菜单转发不会启动每日奖励请求。其他平台不会调用这些微信接口。接口异常记录到控制台，不阻断游戏启动或游戏内主动分享。

微信官方文档目前将小游戏朋友圈分享标为 Beta、暂只支持 Android，具体可用性仍由微信客户端决定。参考 [showShareMenu](https://developers.weixin.qq.com/minigame/dev/api/share/wx.showShareMenu.html) 和 [onShareTimeline](https://developers.weixin.qq.com/minigame/dev/api/share/wx.onShareTimeline.html)。

数值统一在 `assets/scripts/core/EconomyConfig.ts` 的 `dailyShare` 分组维护：`diamonds: 80`、`dailyLimit: 1`。`dailyLimit` 支持 0（暂停）或 1。线上到账金额以服务器回执为准，配置通过 `npm run rewards:export` 导出至 PHP，`npm run rewards:check` 验证一致。

`PlatformProviderRegistry.registerShare(channel, factory)` 接入平台适配器，`createGamePlatform().createShare()` 提供统一入口。接口结果区分 `confirmed`、`unverified`、`cancelled`、`failed`、`unavailable`。微信返回 `unverified`，只封装 SDK 与前后台事件，不操作钱包。主动分享默认标题为「三只小狐狸，能闯到第几关？」，未指定图片时仍使用游戏截图，调用方可覆盖标题、图片和 query。
