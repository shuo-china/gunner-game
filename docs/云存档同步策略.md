# 云存档同步策略

2026-10-23 调整：减轻小型服务器的常规存档请求，并避免错误兑换码触发云存档故障提示。无需修改 PHP 接口或数据库。

## 保存与读取节奏

`assets/scripts/session/CloudSaveStorage.ts` 的 `CLOUD_SAVE_POLICY` 集中维护网络间隔。本地事务仍立即写入账号隔离的日志并读回校验；以下间隔只限制网络请求。

| 操作 | 当前策略 |
| --- | --- |
| 普通收益与前台检查点 | 首次变更后 60 秒合并上传；持续变更不无限延后 |
| 升级、结算等关键变更 | 5 秒防抖，连续操作最多合并 15 秒；仍须满足距上次成功上传至少 30 秒 |
| 切后台 | 尽力提交已写本机的进度；距上次上传尝试及成功上传至少 30 秒，遵守失败退避，重复后台事件不会连发 |
| 切回前台读取云档 | 距上次成功读取至少 5 分钟；并发恢复事件共用在途请求。读取本身不强制上传本地变更 |
| 普通同步失败 | 15、30、60、120、240 秒递增退避，之后最多每 300 秒重试一次；保留原请求 ID 和快照 |
| 签到状态读取 | 由 `GameBootstrap` 缓存 15 分钟，并按服务器给出的跨日时间提前刷新；打开面板与恢复前台复用缓存 |

启动恢复、真实签到/兑换/离线奖励事务、玩家处理存档冲突仍执行所需的即时请求，不受普通自动保存间隔阻止。奖励提交前必须先确认当前存档；丢失回执时仍用原请求 ID 恢复，不会依靠本地发奖。新收到的奖励回执同样作为成功同步时间，后续自动写入继续遵守 30 秒间隔。

## 提示与错误分类

界面使用 `displayStatus`，内部 `status` 继续记录真实操作状态。一次同步持续不足 3 秒时不显示“正在同步进度”；普通网络同步连续失败达到 3 次后，才显示“进度已存本机 · 等待云端同步”。成功后清除失败计数和提示。

空兑换码或仅含空白字符的输入在本地立即返回无效兑换码，不写存档、不上传、不发奖励请求。`REDEEM_INVALID`、`REDEEM_ALREADY_USED`、`REWARD_INVALID`、`DAILY_NOT_CLAIMABLE` 与 `REWARD_WALLET_LIMIT` 的明确 4xx 业务拒绝只反馈对应业务原因，清除该次未获奖请求，不计入存档失败，也不会留下等待云同步提示。多设备冲突、账号或存档异常、本机写入失败和未确认奖励继续即时阻止危险的后续操作，不为降低提示频率而延迟保护。

## 数据保护与验证

服务器版本比较与交换、奖励账本保护、账号/后端隔离及两份冲突快照备份保持不变。未上传的最新进度保留本机；冷启动会先读取并恢复当前账号日志，不会因减频而直接创建新档。仅支持当前完整 v3 存档和奖励状态：武器目录为 v4，余额精度、玩法区块、教学计数与奖励账本均须存在。缺字段或不支持的格式停止恢复并保留原数据，不绑定旧本地档、不迁移目录、不从日期推断广告次数。只有没有云档和待恢复日志的新账号创建初始进度。

`tests/cloud-save.test.cjs` 使用可控时钟验证 60 秒普通合并、关键操作持续发生时至少 30 秒的成功间隔、后台间隔与退避、连续失败提示门槛、慢请求提示、重复错误兑换、5 分钟读取缓存、20 次并发恢复仅发一次读取，以及恢复后重置缓存。连同 `tests/backend-rewards.test.cjs` 的定向验证共 60 项通过；覆盖空白兑换不发请求且不写盘、奖励原子提交、超时重试、旧回执、账本冲突和账号隔离。全量 `npm run check` 由发布流程另行执行。
