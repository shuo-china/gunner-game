# 转生接入说明

本功能以 Cat Gunner 1.1.61 的原生反编译逻辑、ARM64 数值运算及序列化界面为依据，接入普通转生、三项永久强化和两秒转生特效。当前正式和测试配置的广告总开关与五个广告位均已开启，转生广告强化入口按业务条件展示；付费强化入口、确认框及资源已删除。测试包提供模拟广告，正式包尚未接真实广告 SDK，请求返回失败、不发奖。下文截图和验证记录保留各自版本的历史结果。规则和资源按原版还原；本文不代表 Unity 与 Cocos 任意帧或像素完全一致的视觉验收证明。

## 玩家流程与门槛

历史最高进度达到第 3 关后，左侧转生入口解锁。进入主面板可查看紫色货币、当前可获得奖励和三项永久强化；普通转生与广告强化分别打开原版确认框。面板及确认框打开期间战斗继续，只静音枪声。

内部 `stageIndex`、`waveIndex` 从 0 开始，波次范围为 0–4。这里有两个不同的进度计算，不能混用：

| 用途 | 原版规则 |
| --- | --- |
| 入口解锁 | `weapons.stageValueMax >= 20`，历史进度编码为 `stageIndex × 10 + waveIndex` |
| 执行转生 | 当前逻辑 `stageIndex >= 2`，即当轮已到第 3 关 |
| 奖励进度 | `p = stageIndex × 5 + waveIndex` |

通关时逻辑索引先推进，旧战场仍可停留在胜利过场，因此奖励和执行门槛使用逻辑位置，不能只读取屏幕上仍显示的旧关卡。转生回到 1-1 后入口仍解锁，但必须再次到第 3 关才能执行。

广告强化奖励为普通奖励的三倍，每个设备本地自然日一次。成功完成广告后进入两秒动画；只有动画完成、转生事务提交时才消耗次数，日期也取提交当天。取消、失败或失效票据不发奖、不重置、不消耗次数。当前 Web 和微信的测试包使用模拟广告面板，可选择成功、取消和失败；正式包使用不可用提供者，尚未接真实广告 SDK。

付费强化入口、确认框、价格、配置及独占图片已删除；每日广告次数耗尽后仅显示不可用的0/1按钮，不再提供付费替代。广告模拟面板已统一为公共模块，播放期间暂停战斗，接入方式与本轮验证见 [奖励广告说明](奖励广告说明.md)。本文后续历史截图中的付费内容不代表当前版本。

## 重置与保留

| 分类 | 处理 |
| --- | --- |
| 金币 | 余额归零 |
| 三项普通金币升级 | 攻击力、攻击速度、金币获取等级归零 |
| 当前与待开始关卡 | 回到第 1 关第 1 波；同时清除旧转场、待跳关和奖励事件，并产生新的 `roundId` |
| 武器与装备 | 保留背包、装备位、图鉴、保护锁、装备位星级及升星失败补偿 |
| 其他货币和权益 | 保留钻石、星石、武器广告权益及其原有到期时间；转生不刷新期限 |
| 历史进度 | 保留 `weapons.stageValueMax`，已解锁入口继续可用，历史关移动加速继续生效 |
| 转生成长 | 保留并累计紫色货币、三项永久等级、转生次数和广告强化使用日期 |
| 尚未实现的系统 | 不补造当轮累计金币、任务、评价等字段或外围行为；后续按原版证据接入 |

会话原位重置，不重新构造 `BattleSession`。测试环境在首次转生前仍会于启动时补足普通升级预算；一旦转生次数大于 0，刷新测试档也不会返还被清空的金币。钻石仍沿用原有测试环境补款规则。

## 数值与实际战斗

`OriginalInfVal` 将金额和原版有效数字精度分开保存。整数构造保留整数位数精度，双精度构造按 G17 转换并使用 17 位精度；加减先对齐并截断操作数，乘法、除法和快速幂在对应步骤截断。第二轮对照确认普通金币累计和扣款也经过原版 `InfVal`，现已与紫币一样保留运算精度；`DecimalAmount` 仍提供底层精确计算，不全局改变其行为。当前金币和紫币存档都必须保存合法的 `digits/exponent/precision`，缺失或非法精度不再自动推断；测试金币预算单独提供足够精度，仍可购买全部普通升级。

普通奖励按以下顺序计算：以原版整数精度计算 `p²`，乘由双精度平方根构造的 `sqrt(p)`，乘遗物奖励百分比，再除以 100，最终保留五位有效数字。广告奖励在此结果上再按原版精度乘 3。遗物系统尚未实现，默认奖励百分比为 100；不能直接用 `Math.pow(p, 2.5)` 替换整条运算链。

| 当前位置 | `p` | 普通奖励 | 广告强化奖励 |
| --- | --- | --- | --- |
| 第 3 关第 1 波 | 10 | 316.22 | 948.66 |
| 第 3 关第 2 波 | 11 | 397.99 | 1193.9 |

主面板打开或升级后刷新奖励；打开确认框重新计算；两秒动画结束的实际结算再次计算。紫色货币加减也保留 `OriginalInfVal` 精度，不能展示为普通数字后再写回。金额为零时可能带有原版遗留指数，序列化需保留原值。

三项永久强化等级均为 0–20000，使用同一价格曲线：

- 攻击力和金币获取加成按原版 `1.05` 快速幂，计算 `100 × 1.05^等级 − 100` 后去小数、截为三位有效数字；返回实际百分比时再按原版加法加 100。
- 攻速每级增加 5 个百分点，和普通攻速升级相加。
- 当前等级 `n` 的下一次升级基础价格为双精度 `3 × (n + 1)^1.6`；`n > 15000` 后额外乘按 `1.002` 递推的累计系数，系数每步截为四位有效数字。最终价格去小数并截为三位有效数字；20000 级没有可购买价格。
- 购买支持单击及长按；等待 0.4 秒后，每 0.04 秒执行一次。按原版协程，慢帧每帧最多执行一次重复购买，不追补一批升级。

永久强化接入实际战斗：武器伤害依次乘普通攻击百分比和转生攻击百分比，去掉小数后再应用装备位星级倍率；树木金币乘普通金币百分比及转生金币百分比后入账。原版实际加载的普通攻击／金币 0 级表项保留五位精度，之后各级为三位；永久攻速表始终为五位。攻击速度先读取原版 `Speed_return`：将卡片上的 `5 × 永久攻速等级` 按 `InfVal` 加 100，再转换为整数。实际速度使用 `普通攻速百分比 + Speed_return − 100 − 30 × stageIndex`，限制到 100–10000%，再将武器射击间隔限制到 0.05–2 秒。例如永久攻速 199 级的 `995 + 100` 正确得到 `1095%`；19999 级则在五位精度下由 `99995 + 100` 截为 `100090%`。这些精度取自序列化表，不能以未被运行时调用的 `Balance_Reload` 整数构造替代。

## 生命周期与扩展接口

`RebirthSystem` 是纯逻辑模块，持有紫色货币、永久等级、广告票据及 `idle → adPending → animating` 状态；普通转生直接从 `idle` 进入 `animating`。UI 只调用会话接口，不直接修改存档。

| `BattleSession` 接口 | 用途 |
| --- | --- |
| `getRebirthState()` | 查询货币、等级、价格、奖励、门槛、每日状态和动画进度 |
| `requestRebirth('normal' \| 'ad')` | 校验门槛和忙碌状态；广告请求返回独立字符串票据 |
| `completeRebirthAd(token, outcome)` | 提交 `success`、`cancel` 或 `failure`；拒收错误、过期及重复票据 |
| `cancelRebirthAd()` | 取消未完成广告，不取消已开始的转生动画 |
| `advanceRebirth(dt)` | 累积动画时间，结束后统一提交奖励、次数和重置，保存一次并返回新 `StageRound` |
| `purchaseRebirthUpgrade(type)` | 购买 `power`、`speed` 或 `money` 永久升级，校验价格和上限后保存 |
| `setRebirthModifiers({ rewardPercent })` | 接入未来遗物奖励百分比，默认 100；该接口本身不持久化外部系统 |
| `onRebirthCompleted(state)` 构造参数 | 保存后通知未来任务或评价等模块；回调异常不会打断已提交转生 |
| `configureRebirthTest(...)` | 仅测试环境可设置 `ruby`、`levels`、`count`、`adUsedDate`，正式环境返回失败 |

现有重置参与项集中放在 `BattleSession.advanceRebirth`：经济模块清金币及普通等级，关卡模块清当前/待开始关卡、奖励账本和旧转场。新增成长模块时，先确认原版是否重置，再把必要的状态准备和提交加入这里；不能默认清空所有新增系统。保留类模块不注册重置动作。完成通知应放在保存之后，不从通知回调再次发放本次奖励。

转生特效开始时停止当时所在关卡的战斗和计时，已开始的关卡转场继续推进。原版 `Loading_Then_Start` 的等待不检查 `is_Play`，而其 `Game_Start` 会重新开启战斗：若旧转场先于两秒特效完成，则新关卡会在剩余特效期间正常战斗和计时，也可能改变最终结算时重新读取的逻辑进度。会话按特效开始时的 `roundId` 记录停战范围，保持这一行为。两秒事件提交时，原版 `Rebirth_Reset` 先将索引归零，再通过 `Game_Exit` 停止已有计时和转场、清除过场 UI，随后从 1-1 开始；当前事务按同样顺序清理。旧 `roundId` 事件不能给新局结算。

角色和视图使用专用重置方式：`world.reset(..., { preserveActorState: true, rebirth: true })` 与 `battlefield.reset({ preserveCharacterState: true, preserveTransientEffects: true })`。保留角色实例、跟随 AI、攻击计时、目标切换记忆、Animator 和 recoil，清旧目标并重新定位；主角自动索敌计时归零。特效停战期间主角在无摇杆输入时停止移动，AI 猫按原版 `SmoothStop` 以 `8 × deltaTime` 衰减余速度；物理步仍推进它们的位置，速度平方低于原版阈值后才切为空闲动画，AI 状态和攻击计时保持冻结。弹丸、手脸缓动、Animator、recoil 和视觉效果也继续运行，不做全局暂停。

转生结束重建地图时，原版独立根 `Polling_manager/Bullet`、`Polling_manager/Bullet_FX`、`Particle_Polling/Money_Polling` 与数字池不会随 `Tree_manager/Map_obj` 清除。当前同样保留飞行弹丸的原伤害、已命中对象、剩余寿命及全局特效，并保持物理和特效时钟连续。例如旧过场在转生特效期间重新开战后发出的弹丸，能够继续飞进重置后的 1-1；普通重开局的既有清理行为不受这项修改影响。倒计时若已在上一帧降到零，下一帧即使开始转生仍先触发失败过场；原 `Game_Cor` 的零点判定先于 `is_Play`，只在剩余时间大于零时才因转生停止扣时。

弹丸命中表按原 `Collider.GetInstanceID()` 的稳定身份保留：`Tree_Grid.Spawn` 重新启用序列化 `Tree_list` 的原对象，没有销毁或新建碰撞体。当前树的 `id = grid × 100 + slot` 表示相同固定池槽，而非当前活动列表序号；同一飞弹转生前已击中的槽，重生后仍不再受这颗弹伤害，其他未命中的槽照常受伤。不能因 JavaScript 重建了 `TreeState` 就清空命中表或给所有树换一轮 ID。

切后台会暂停动画时间并取消尚未结束的模拟广告。返回前台继续动画，后台时间不补算。提交前刷新只恢复已有持久状态，不发本次转生奖励、不扣广告次数；提交后刷新恢复完整的转生结果。两种情况都不恢复半段动画或广告票据。

## v3 存档

继续使用 `forest-gunner:economy:v3:test` 和 `forest-gunner:economy:v3:production`，不改版本号或 key。只支持完整当前格式，`rebirth` 为必填块：

```json
{
  "rebirth": {
    "ruby": { "digits": "31622", "exponent": -2, "precision": 5 },
    "levels": [0, 0, 0],
    "count": 1,
    "adUsedDate": "",
    "adUsedCount": 0
  }
}
```

`levels` 顺序固定为攻击力、攻击速度、金币获取。`ruby` 金额为系数乘以十的指数次方，`precision` 是独立的运算精度；示例余额为 316.22。`count` 是已提交的转生次数；`adUsedDate` 是最近成功提交广告强化的本地 `YYYY-MM-DD`，未使用时为空字符串；`adUsedCount` 显式保存该日已用次数，不从日期推断。

只有新账号创建零货币、零等级、零次数和空日期。已有存档缺少该块、广告次数或其他字段非法时拒绝恢复并禁止覆盖原档，保留有效金币、武器和进度的原始数据。验证包括数值格式、精度、非负余额、三项 0–20000 级及合法次数。动画阶段、广告票据、奖励 modifier 和外部任务状态不在该块中保存。

## 界面复核与交互细节

2026-10-10 上一轮按 743×1320 游戏区域对照原版与 Web 的主面板、普通确认框和广告确认框。面板、天使猫、图标、按钮及层叠关系继续使用原序列化布局；浏览器截图的颜色管理差异不能用来修改源颜色。原 CanvasScaler `level0:124022` 的参考分辨率为 1080×1920，`m_MatchWidthOrHeight=0`，因此当前仍按宽度缩放；主面板底边贴安全区域底部，确认框按原锚点居中。三种竖屏及安全区位置已有组件回归覆盖。

转生文字使用从原字体及 TMP 材质、字形数据生成的图集，按原字形指标排版，不再依赖平台 TTF 加载。数值的原 `m_characterSpacing=9`、字体缩放、描边、阴影以及说明句内紫币的字形尺寸与基线分别保留。中文正文的原垂直对齐为 `512`（居中），不是按实际字形外框居中。原中文动态 atlas 在发布资源中为空，中文图集由原字体轮廓与材质参数重建；上一轮最终运行截图已复核，但字体抗锯齿与原 Unity 仍有微小差异，不能宣称逐像素完全相同。图集生成与运行排版数据保存在转生配置中。

按钮使用原版 0.1 秒 ColorTint 过渡，按下颜色为 200/255、悬停和选中为 245/255，并保留独立的 BounceBtn 缩放。广告次数耗尽、尚未满足付费显示条件时，`0/1` 按钮虽无持久化 OnClick 操作，原运行时仍绑定失败音 5，现已恢复。不可购买的永久升级保留按压反馈，但不会购买或播放成功音；长按协程在每次重复前先检查购买条件，不足时停止，既不继续购买，也不因关卡推进刷新主面板奖励。入口锁定使用原 `Alarm/StageUnlock` 文案，当前关卡不足以执行转生则使用 `Rebirth/Rebirth_Warn`。

本轮补齐原版指针行为：按住后移出按钮会停止重复购买，但保留本次按压；移回不会重新启动重复购买，内部松开仍可点击。外部松开用原 0.1 秒恢复缩放且不执行操作，真正的系统取消另行处理。命中范围按按钮下各个 Graphic 的实际矩形分别判断，包含伸出按钮图片的标题文字，不包含矩形之间的空隙；缩放使静止指针离开命中范围时也会停止长按。确认框同时阻断新触摸和底层已捕获的触摸，子节点事件只向按钮执行一次。快速重按保留原 BounceBtn 协程的共享计时行为；打开确认框或开始特效时，底层按钮继续完成松开动画并保留选中颜色。

十个特效圆形依原动画在 0、1/6 秒至 1.5 秒依次启用，各以 0.3 秒线性从 0 缩放到 1。原 `BounceStart` 的 `Middle_value` 和 `WantSize` 均为 1，因此没有额外的缓动或回弹曲线；两秒处统一执行转生事件。
