# 皮肤系统

本模块依据 Cat Gunner 1.1.61 的 `Skin_manager`、`Skin_Info_UI`、`Skin_Item_UI`、`Cat` 代码和原 Unity 序列化资源实现。包含 25 款皮肤、四列滚动列表、详情翻页、钻石购买、全队外观切换及持有加成。皮肤入口位于主线左侧菜单，列表没有分类页签。

## 当前狐狸毛色（2026-10-19）

当前使用共用狐狸骨架与 2026-10-19 重新生成的统一轮廓服装，在原版奶油、灰棕、浅蓝、粉紫等毛色思路上，按现有服装主题配置 25 种毛色。编号 1 保留基础橙色；苔叶游侠为鼠尾草灰、蓝港水手为晴海蓝、紫晶术士为薰衣草紫、黑金机师为石墨灰等。完整色值维护在 `skin-system/visuals.json` 每款的 `furColor`，中文色名在 `design.furPalette`；`handColor` 必须与 `furColor` 一致。

`original-sprite.effect` 的 `SKIN_FUR_PALETTE` 变体在 sRGB 解码前替换原橙色贡献，保留奶油色区域、深棕描边及透明边缘。`CatView` 只为头、耳、四肢和尾巴使用该材质，衣服使用下文的共用轮廓材质；持枪手沿用 `handColor`。`SkinHud` 的列表和详情直接展示同一套战斗部件和毛色材质，不再使用独立预览 PNG 或预览专用调色分支。

`SkinVisualAssets` 按基础材质和皮肤 ID 缓存材质，全队与界面各自的线性材质复用，由 `ArtLibrary.dispose()` 随场景销毁。回到编号 1 时恢复基础材质。原 V9 安装/导出脚本不含本次色表及加粗衣服，重新导出时必须保留当前服装、`furColor` 和相应的 `handColor`，不能恢复全部橙色。

## 规则与界面状态

皮肤功能由 `ContentUnlockManager` 的 `skins` 规则统一控制：主引导的五个步骤期间隐藏入口，完成装备教学、进入 `done` 后开放；没有额外关卡门槛。依据原版场景引用 `Tutorial_manager.DisableOnTutorial[5] → Skin_Btn`，以及 `Tutorial_manager.BeginTutorial/CompleteTutorial` 的隐藏和恢复逻辑。购买、换装和直接打开面板均检查此规则。普通测试档默认跳过引导而开放；显式开启引导时（包括隔离预览），即使绕过关卡进度也必须完成教学。

微信 0.1.8 将此规则合入实际发布源码；0.1.7 发布副本未包含这项改动。发布验收同时检查正式新档画面、隔离引导预览和最终微信压缩代码中的会话规则，不能只依据工作工程的测试结果。现有服务器提示字体若缺少新文案字符，`OriginalAlerts` 会临时使用系统字体，下一条完整覆盖的提示恢复原字体；远程资源可继续沿用已部署版本。

内部 ID 为 `0–24`，界面编号为 `1–25`。编号 1 的基础皮肤默认拥有并装备。功能开放后，其他皮肤可直接购买，不要求按顺序购买，也没有单款关卡门槛。测试环境和正式环境都只默认拥有基础皮肤；测试钻石补给不等于解锁全部皮肤。

| 项目 | 内部 ID 为 `i` 的规则 |
| --- | --- |
| 价格 | `100 × i` 钻石，最高 2400 钻 |
| 全收集总价 | 30000 钻 |
| 攻击力加成 | `16 × i`% |
| 攻击速度加成 | `10 × i`% |
| 金币获取加成 | `5 × i`% |
| 全部持有后的累计加成 | 攻击力 +4800%、攻击速度 +3000%、金币获取 +1500% |

加成按**全部已拥有皮肤累计**，不取决于当前装备。购买立即扣钻并增加持有加成，但不自动装备；装备只改变全队外观，不再扣费，也不再次叠加属性。打开详情和翻页均不产生购买或装备操作。

列表保留四列、七行和第七行单卡，使用原 `ScrollRect` 的垂直拖动、惯性、弹性与遮罩。详情关闭后保留列表滚动位置。未拥有的卡片有原锁定遮罩，详情显示黑色角色和锁；余额足够才可购买，余额不足时价格为原红色、购买按钮不可交互。拥有后显示装备按钮，已装备时显示绿色勾选；第 1 款隐藏上一页，第 25 款隐藏下一页。

文案、价格内联钻石、按钮颜色过渡、`BounceBtn` 缩放和音效引用来自原资源。点击、拖动取消、多指归属、关闭、失焦与尺寸变化由 `SkinHud` 管理。弹窗打开时阻挡其他入口和金币升级、隐藏教程提示并静音射击音效；后台战斗与弹丸继续按既有规则更新。切换其他功能、进入战斗模式或转生展示会关闭皮肤弹窗；切后台和手动暂停取消当前手势。

## 领域接口与存档

`SkinCatalog.ts` 提供 `SKIN_COUNT`、`SKIN_CATALOG`、`getSkin(id)`、`isSkinId(id)`。`SkinSystem` 仅持有所有权和选中 ID，不依赖 Creator，也不直接持有钱包。UI 通过 `BattleSession` 提交交易：

| 接口 | 返回与职责 |
| --- | --- |
| `getSkinState()` | `SkinSnapshot`：`selectedId`、`diamonds`、复制的 `owned`、25 个 `items`、`totals` 和 `revision` |
| `purchaseSkin(id)` | 校验 ID、所有权、余额和会话阶段；使用 `WeaponInventory.spendDiamonds` 扣款，将余额与所有权合并保存后通知属性刷新 |
| `equipSkin(id)` | 只允许选择已拥有皮肤；更换选中 ID 后保存，由入口同步 `BattlefieldView.setSkin` |

`items` 包含目录字段以及 `owned`、`equipped`、`affordable`。`totals` 只包含额外百分比，不含基础 100%。`SkinActionResult` 为 `{ ok, reason?, skinId?, changed? }`；失败原因包含 `invalid`、`owned`、`locked`、`contentLocked`、`diamonds`、`busy`、`mode`。`contentLocked` 表示教学未完成、整个皮肤功能未开放，`locked` 表示尚未拥有所选皮肤。非主线模式、Raid 准备或入场流程、转生流程、待完成的武器广告、重入交易优先拒绝皮肤命令；入口另拦截暂停、未就绪和模式 Loading 尾帧。HUD 通过 `getContentState()` 回调获取同一规则，限制恢复时关闭面板并取消延迟换装。

购买成功后只在钱包和所有权提交完整时触发一次强制配装刷新，重置活动猫的散布，保留攻击计时和已经发射弹丸的属性。装备不触发此属性刷新；重复装备当前皮肤没有存档变化或部件重建。

沿用 `forest-gunner:economy:v3:test` 和 `forest-gunner:economy:v3:production`，新增可选块：

```json
{
  "skins": {
    "owned": [true, false, false, false, false, false, false, false, false, false, false, false, false, false, false, false, false, false, false, false, false, false, false, false, false],
    "selectedId": 0
  }
}
```

旧 v3 没有 `skins` 时使用基础皮肤初值。恢复时要求 25 个布尔所有权、基础皮肤已拥有，以及选中项合法且已拥有；损坏的皮肤块整体回退，不丢弃其他有效钱包、武器、进度或成长块。转生保留所有皮肤和选中 ID。刷新回主线并恢复外观，不恢复列表滚动、详情页或手势。UI 不直接编辑存档，游戏不读取或修改原版存档。

开放状态由现有教学存档推导，不新增皮肤解锁标记。旧档若教学尚未完成，会隐藏入口并限制新的购买和换装，但已有皮肤、当前外观及持有加成全部保留；教学字段缺失或损坏时，沿用既有兼容规则视为教学完成。完成后刷新、转生均保持开放。

## 各模式数值与原版精度

皮肤影响伤害、攻击间隔和符合条件的树木金币；不会增加 Boss 的固定钻石奖励、Raid 星石或转生紫币奖励。原版代码依据为 `Cat__t7445.c` 的 `Balance_Reload`、`CalculateAtkCoolMax`，以及 `Gamemanager__t7191.c` 的 `MoneyValue_return`。累计百分比来自 `Skin_manager__t7653.c` 的 `Skin_Value_Reload` 和三项 `Accum_return`。

下表中的普通、转生倍率均包含基础 100%；`D/S/M` 分别是皮肤累计额外攻击/攻速/金币百分比，`stageIndex` 为主线零基关卡索引。表内每个“倍率 / 100”都是一次独立的 `OriginalInfVal.mul(...).div(100)`，不能合并成 JS 浮点乘数。

| 模式 | 伤害顺序 | 攻速百分比分母（之后限制到 100–10000） |
| --- | --- | --- |
| Main | 武器基础伤害 → 普通攻击倍率 → 转生攻击倍率 → `(100 + D) / 100` → 去除小数 → 装备位星级倍率 | `普通攻速 + 转生攻速 - 100 + S - 30 × stageIndex` |
| SpeedRun | 与 Main 相同 | `普通攻速 + 转生攻速 - 100 + S` |
| Boss | 武器基础伤害 → 转生攻击倍率 → `(100 + D) / 100` → 去除小数 → 装备位星级倍率；跳过整个普通攻击倍率操作 | `转生攻速 - 100 + S` |
| Raid | 武器基础伤害 → `(100 + D) / 100` → 原鱼与遗物中性乘除 → 去除小数 → 准备槽星级倍率 → 弱点 10 倍 | `S` |

Boss 跳过普通攻击升级时，连等级 0 的有效数字提升也跳过。Raid 不使用普通或转生攻击/攻速升级，保留两个原中性 `×100 ÷100` 运算；入场时冻结武器、准备槽星级与皮肤加成。星级沿用各模式的既有槽位规则：Main/SpeedRun/Boss 按紧凑活动角色索引，Raid 按准备槽索引。尚未实现的 Fish/Relic/Buff 成长保持中性。

所有模式攻击间隔遵循原 float32 顺序：先把原武器间隔除以限制范围后的百分比分母并舍入到 binary32，再乘 100 并再次舍入，最后限制到 `0.05f–2f`。`0.05f` 的 JS 精确表示为 `0.05000000074505806`，不能用普通双精度 `0.05` 替代边界。原皮肤基础攻速 100 在 Boss/Raid 分支被扣除，因此 Raid 的分母是 `S`，不是 `100 + S`；例如只拥有编号 2 的额外 10% 时，Raid 仍被夹到 100%。

Main 与 SpeedRun 的树木金币按原奖励精度依次应用普通金币倍率、转生金币倍率、`(100 + M) / 100`，每次操作保留原 `InfVal` 截断规则，最后加入钱包。皮肤倍数后不额外添加整数截断。事件账本和回合 ID 继续阻止同棵树或旧回合重复入账。实现位置是 `BattleSession.combatLoadout`、`attackSpeedPercent`、`attackInterval`、`consume` 和 `RaidSystem.prepareStart`。
