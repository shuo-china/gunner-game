# 公共奖励广告

> 当前正式和测试配置的总开关 `CONTENT_CONFIG.ads.enabled` 均默认关闭；`weapon-daily`、`weapon-unlock`、`rebirth`、`speedrun`、`raid-entry`、`boss`、`hunt`、`pet-daily`、`fish-daily`、`mine-entry`、`mine-reward` 十一个广告位保留各自配置，须同时打开总开关才会按条件开放，见 [内容解锁说明](内容解锁说明.md)。`weapon-auto` 已移除，自动合成开放后免费。模拟广告仅用于测试包；正式包尚未连接真实SDK，广告请求返回失败、不发奖。下文验证记录保留各自版本的历史结果，各新增模式的本轮运行结果见对应说明。

项目已移除PlusPack、扫荡、免广告促销、付费转生的全部入口、弹窗、展示字段、价格文案和独占图片。普通金币升级、钻石抽枪、星石升星、转生货币强化与免费奖励广告继续保留。旧v3存档中的未知付费字段被白名单恢复逻辑丢弃，不会变成免费权益。

## 共用模块

`session/RewardedAds.ts`定义唯一的广告结果、入口类型和提供者接口。`RewardedAdService`全局只允许一个展示请求，用递增requestId隔离旧回调；业务token保留在游戏内，不交给广告平台。`SimulatedRewardedAdProvider`与唯一`view/RewardedAdModal.ts`提供统一的“模拟广告／成功／取消／失败”界面。各HUD只申请展示与接受结果，不再各自构造广告弹窗。

| placement | 业务所有者 | 成功后的当前行为 |
| --- | --- | --- |
| `weapon-daily` | WeaponInventory | 当天一次随机C级武器；完成时重查背包 |
| `weapon-unlock` | WeaponInventory | 领取待确认的限时武器 |
| `rebirth` | BattleSession/RebirthSystem | 进入2秒特效，随后统一保存三倍奖励、次数和重置 |
| `speedrun` | BattleSession/SpeedRunSystem | 已结算120钻基础上追加360钻，总计480钻，然后退出挑战 |
| `raid-entry` | BattleSession/RaidSystem | 每日2次免费用尽后，额外进入1次Raid；广告成功并完成入场校验才消耗当天广告次数 |
| `boss` | BattleSession/BossSystem | 已结算600钻基础上追加1200钻，总计1800钻，然后退出独立Boss；取消/失败留在胜利页 |
| `hunt` | BattleSession/HuntSystem | 每小关奖励已即时到账；结算广告追加本局累计宠物币一次后退出，保存失败停留并重试 |
| `pet-daily` | BattleSession/PetSystem | 首次狩猎通关后默认每天领取一只C阶；成功时再次校验日期、背包与库存版本 |
| `fish-daily` | BattleSession/FishSystem | 使用每日免广告次数后，广告成功发鱼并提交当天次数 |
| `mine-reward` | BattleSession/MineSystem | 追加已取整矿山基础钻石的3倍后退出，合计4倍；取消/失败保留基础奖励 |
| `mine-entry` | BattleSession/MineSystem | 增加300秒全局3倍攻速（上限900秒），正常扣票进入矿山 |

取消、失败或失效回调不发奖；取消后可按原业务规则重试。广告展示暂停战斗时钟，成功或取消后恢复，原本的手动暂停保持。切后台、销毁和关闭所属界面会取消未完成请求；尺寸变化清理旧触摸，防止旧手指在新请求中误领取。即使提供者清理抛错，业务回调也只结束一次。所有奖励广告繁忙时都会推迟待领取武器的过期删除，广告结束立即重查。

Raid广告token只在当前页面实例、当前日和当前周有效；跨日或跨周刷新会取消旧请求，不能扣除新周期次数。入场前还会复核所选武器来源；取消、失败、来源变化、重复或过期回调都不会发放一次隐式入场。刷新只恢复已保存的使用状态，不恢复token。该广告只增加入场，不加倍星石，也不解锁付费任务奖励。

## 后续接入多平台

当前测试环境使用模拟广告面板；正式环境由 `platform/PlatformServices.ts` 选择广告提供者，默认仍为 `UnavailableRewardedAdProvider`，返回失败、不发奖，尚未接真实广告SDK。登录渠道与广告提供者分别注册，TapTap 小游戏、TapTap 安卓包、抖音和微信可以有不同的广告实现，也可在适用的平台复用广告提供者。接入时实现 `RewardedAdProvider`，使用 `registerAds` 注册，在 `platform/PlatformConfig.ts` 配置渠道自己的提供者及广告位 ID；无需更改 `GameBootstrap` 或各 HUD。详见 [多平台登录与广告接入](多平台登录与广告接入.md)。

提供者的`show(request, complete)`只报告完整观看、取消或失败，并返回本请求的监听清理函数。完整观看才能报告`success`；加载/播放失败报告`failure`；提前关闭报告`cancel`。广告位ID和平台生命周期处理留在提供者内，不写进各HUD；真实SDK接入后需另验设备前后台行为。广告奖励仍由当前本地玩法结算，尚未接服务端广告验证或发奖。
