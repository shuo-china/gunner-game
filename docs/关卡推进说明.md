# 主线关卡推进

主线依据原版 `Tree_manager`、`Tree_Grid`、`GameSlider` 的反编译逻辑及序列化 UI 资料接入。当前采用 TypeScript/Cocos 实现；规则、资源和动画参数有对应来源，不将此说明视为 Unity/Cocos 逐帧或像素完全一致的验收证明。

## 关卡是否有终点

原版没有设计上的最终关。内部 `Stage` 和 `Level` 从 0 开始，界面显示 `Stage + 1`、`Level + 1`；每关五波，完成第五波后 `Stage` 加一、`Level` 归零。历史进度使用 `Stage * 10 + Level`，不能替换为连续波次序号。

`PrecomputedStageCount = 5000` 是预计算表长度，不是关卡上限。基础树生命从 250、基础金币从 20 开始，表内按原版逐项乘 3、截断为两位有效数字；第 5001 关及以后使用表尾值乘原版 `PowOfThree` 继续计算。该快速幂在乘法和平方步骤同样截断，不能直接替换为普通浮点 `Math.pow(3, n)`。

地图和树外观按 `Stage % 10` 循环，数值继续增长。无预设终点不等于无限计算资源：本实现关卡索引及大数指数须能表示为 JavaScript 安全整数，存档只对系数字符串长度及精度设置资源预算，不按指数大小限制关卡或钱包。游戏金币按原版 `InfVal` 对齐并截断加减；底层大数计算仍受设备计算和内存资源限制。

## 每波生成与结算

- 第 1–5 波分别启用 1–5 块网格，每块生成 `min(100, Stage * 10 + 30)` 棵树。第五波另加一只 Boss，最多 501 个目标。
- 各波普通树 degree 比例依次为 `80/20/0`、`50/45/5`、`20/55/25`、`5/35/60`、`0/15/85`。Boss 是独立目标。
- degree 0–3 的生命倍率为 `1 / 1.8 / 3 / 35`，金币倍率为 `1 / 1.8 / 3 / 100`。死亡金币再乘当前金币升级百分比，即时入账；主线清场没有额外直接发钻逻辑。
- 北边界随波次移动，角色、弹丸、粒子和地图表现使用同一轮定义。生命、伤害和金币使用 `DecimalAmount`，血条用大数比值生成 `[0,1]` 范围的展示值。
- 每局有递增 `roundId`，会话忽略旧局事件；同一棵树及同一完成事件不能重复发奖或推进。该局最后一笔金币、下一局索引与历史最高进度统一保存。

## 主线自动寻树

主猫按原版 `Cat.FindNearestTreeByGrid` 先筛网格，再比较树的距离评分。每棵普通树记录所属网格的原点 Z（50、100、150、200、250），不从树的抖动坐标或当前数组下标推算。网格距离沿用原版 `[原点 Z, 原点 Z + 45]` 范围；按距离升序搜索，同距离保持原网格顺序。当下一网格距离大于已找到的最佳评分时停止搜索。第五波 Boss 独立参与最后比较。

树的评分仍为根节点 XZ 距离；距离超过 8 时加上 `0.4 × max(0, 树 Z − 主猫 Z)`，同分保留原池顺序。尚未锁定可攻击目标时，每 0.3 秒重搜，移动目标为空或死亡时立即重搜。挑战、矿山、独立 Boss、讨伐和狩猎不使用主线网格筛选。

2026-10-16 起，主线和挑战优先保持当前有效攻击目标：目标仍存活、位于屏幕内且在攻击射程内时，其他目标评分更低也不抢占。移动、瞄准和攻击共用该目标；旧锁死亡、被移除、离屏或超距后立即重新选敌，并在同一帧更新移动和攻击。尚未进入射程的移动目标仍可继续接近。拖动摇杆保留原有手动移动和射线瞄准，松手后优先续打仍有效的当前目标。该规则是明确的体验调整，普通主线不再照搬原版周期重选覆盖有效攻击锁的行为。

## 原版计时与过场

默认每波 180 秒。倒计时由会话状态机持有，前后台暂停不扣时间。按原版协程顺序，减到零后在下一次恢复检查时失败；该检查前已处理的最后一击仍可获胜。

胜利自动推进，失败自动重试同一波。普通流程先展示结果 2 秒、Loading 1.5 秒，再启动新局；新局已开始战斗时 Loading 继续覆盖 0.2 秒。目标进度严格小于历史最高进度时，结果和 Loading 的等待改为 1 秒、0.75 秒，角色移动 ×2；这不改变倒计时或射击频率。胜利不等待金币粒子结束才推进。

过场期间，已发射弹丸继续运动并可显示伤害数字，但不再扣除树木生命或触发弹跳。自动切关沿用角色的攻击冷却，不因新波次开始额外重置射击节奏。

胜利、失败、Loading、跳关和移动加速提示使用原版导出资源及序列化布局/动画。跳关提示独立计时，可与新局最后 0.2 秒 Loading 共存；新过场不会被旧过场的收尾误关闭。

Relic 跳关仅在正常推进一次后再尝试额外推进一次，且额外目标必须严格小于历史最高进度。默认概率为 0，此时不抽取随机数。当前版本已移除付费 PlusPack 及其延长时限权益，主线每波固定 180 秒。

## 会话接口与 v3 存档

`BattleSession` 对外提供以下接口：

| 接口 | 用途 |
| --- | --- |
| `round`、`roundId`、`phase`、`canFight` | 获取当前战场及状态，控制是否推进战斗 |
| `consume(events, trees, roundId)` | 批量入账并处理当前局完成事件 |
| `advanceFrame(dt, roundId, paused)` | 推进计时和过场；开始新局时返回 `StageRound`，由入口重建战场 |
| `restartRound()` | 重启当前待开始关卡，保留钱包和成长 |
| `snapshot(...)` | 输出五波 HUD、`stageTransition`、`stageSkip`、`stageReplay` |
| `progressionModifiers` 构造参数、`setProgressionModifiers(...)` | 正式和测试环境均可接入 `{ skipPercent }` 外部参数；跳关概率在胜利时读取 |
| `onStageCleared(round)` | 结算保存后通知任务等外部模块；通知异常不回滚或打断关卡结算 |
| `configureProgressionTest(...)` | 仅测试环境注入关卡、历史进度和分支条件 |

外部 modifier 接口不自动创建 Relic/Fish 成长或广告加速系统，也不会自行持久化外部权益。当前没有遗物系统时维持跳关 0；付费 PlusPack 不在当前接口中。

v3 分别使用 `forest-gunner:economy:v3:test` 和 `forest-gunner:economy:v3:production`，保存钱包、升级、武器及 `progress: { stageIndex, waveIndex }`。历史最高进度只有 `weapons.stageValueMax` 一份来源。旧 v1/v2 key 不读取、不迁移，也不删除。

通关保存的是已推进的目标索引；重新打开时从该波起点开始，不保存树木残血、弹丸、倒计时或半局表现。金币死亡奖励已即时保存。正式环境历史进度达到 30 开启每日广告枪、达到 390 开启保护锁和升星；现有钻石/星石获取缺口仍保留。
