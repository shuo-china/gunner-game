# Raid（突袭）

本模块复现原版突袭的免费准备、选枪、战斗、结算和周任务流程。界面沿用原Unity节点、图片、字体和动画数据；中文入口文案为“突袭”。原界面显示本周成绩，各突袭首领历史记录保存在按GunType索引的存档与只读快照中；隐藏联网排名。付费助手、购买次数、额外任务券、重复领取、星石储蓄及相关购买界面已移除。

Raid（突袭）与 Boss（BOSS玩法）是原版两个独立模块，`BattleMode` 分别保留 `Raid` 和 `Boss`。本文只描述突袭；已接入的独立模式见 [BOSS说明](BOSS说明.md)。突袭内的首领敌人沿用原版 `Raid_Boss` 概念，因此 `RaidBossCombat`、`RaidBossView` 和 `bossIndex` 等名称表示突袭首领，不表示独立的 Boss 玩法。`raid` 存档块、`raid-entry` 广告位及 `raid-system` 资源目录均归属突袭。

## 开放与入场

- 正式环境历史达到第35关显示锁定入口，第40关开放；测试环境直接开放。内部历史值分别为340、390。
- 每日本地日期可免费进入2次。次数在进入加载前保存扣除；加载完成后才计入周挑战次数。中途退出、关闭游戏或刷新不退还已扣次数。
- 广告总开关默认关闭。可选广告位为 `raid-entry`；开启后，免费次数用尽可通过广告额外进入1次，当天仅一次。取消、失败、失效回调或入场校验失败不扣广告次数。
- 进入加载2秒后开始完整60秒。退出立即停战并关闭场景碰撞，1.5秒后重开主线；主线先运行，加载覆盖层再显示0.2秒。

## 选枪与星级

准备页每次打开自动选择推荐的前三把枪。来源为3个装备位和16格背包中已拥有的武器；待广告确认的占位枪不可用，已经领取的同ID武器正常可选。同种枪可以来自不同位置，同一位置不能重复选入。可以留空槽，但不能移除最后一把枪。

推荐排序使用“武器基础伤害 × 对应弱点10倍”，从高到低，数值相同按装备/背包原顺序排列；不把射速、弹数或星级算入推荐权重。领域引用为 `RaidWeaponSource { kind, index, weaponId }`，入场时重新核对位置与武器ID，避免背包移动后误用另一把枪。`sourceIndex`仅作为现有选枪界面的扁平索引，装备为0–2，背包为3–18。

三个Raid槽共享三个永久装备位的星级。Raid使用固定 `raidSlot` 读取星级；战斗角色身份仍压紧为0–2，空槽不会让后面的枪用错星级。这是按本次需求修复的原版空槽错位。星级弹窗复用既有费用、成功率和星石钱包，预览为弱点伤害后应用所选槽星级。

移除原版右侧付费助手栏后，准备页的三个装备栏整体居中，保留原卡片大小和间距；以1080设计宽度计，中心横坐标从原版的 `-390 / -130 / 130` 调整为 `-260 / 0 / 260`，升星和卸装按钮随各自卡片一起移动。

升级限制提示按用户要求改为带红色斜杠的攻击力、攻速图标，并明确显示“金币升级和转生强化提供的攻击力、攻速加成无效。”（分两行）。图标复用装备卡原图，斜杠仅叠加在该提示中；文字使用独立字形图集。武器基础属性、槽位升星和弱点加成仍生效。

入场后冻结所选武器、槽星、皮肤加成和攻击参数。金币攻击升级、金币攻速升级、转生攻击/攻速强化不进入Raid伤害与冷却计算，全部持有皮肤的攻击与攻速加成保留。实际伤害依原分支先处理基础伤害、皮肤倍率和中性鱼/遗物乘除，再整数截断、应用槽星与弱点10倍；保留原InfVal逐步截断精度。尚未实现的Fish/Relic等成长保持中性。攻击间隔按原float32除法再乘100，分母为皮肤累计额外攻速（不加基础100，先限制到100–10000），最后限制在0.05f–2f秒；暴击率为0。Raid战斗隐藏普通金币升级卡片。完整公式见 [皮肤说明](皮肤说明.md#各模式数值与原版精度)。

## 每周突袭首领与战斗

本地周一00:00换周，以2024-01-01为第0周，周索引按5取正模选择突袭首领。对应弱点取原武器表 `getWeapon(30 + bossIndex).type`。每日本地00:00刷新免费和广告次数；时钟只向前推进，回拨设备时间不补次数。使用本地民用日期计算天数，避免夏令时把一周算成不足或多于7天。

独立地图原点为 `(-100, 0)`，突袭首领位置为 `(-120, 20)`。首领复用单个目标实例；每次击杀立即装载下一层满血，不等待死亡动画，不把过量伤害转移到下一层。表现层可以播放死亡与弹跳效果，但不能延迟数值刷新。

初始生命为10,000,000。生命缓存逐层乘以原double `3.0`后保留3位有效数字；实际每层生命使用2位有效数字。不能将显示出来的2位生命再作为下一层增长输入。击杀数从0开始，正在挑战的层数为击杀数加1，没有人为设定的最终层数。

七种武器复用现有战斗与碰撞链。`PIERCE`和`LASER`在Raid首个有效命中后停止，即使该击杀刷新了下一层，也不能继续用同一弹穿过突袭首领；主线激光仍可穿透。导弹冻结目标碰撞体Transform的位置，包含原版Y=-7.4499998，不以球心或地面高度替代。Raid伤害飘字使用实际命中点高度。Raid目标不会发出树木死亡奖励或普通清场事件，所以击杀不给金币、不推进主线、不改变普通挑战进度。

入口层先执行 `world.step(min(frameDelta, remainingSeconds))`，再推进Raid计时并在归零当帧结算；终帧已经发生的命中计入成绩，超出剩余时间的部分不继续攻击。该终帧规则是本次确认的实现行为，不等同于已完成原版协程同帧运行对照。结算和加载期间只推进已有表现，停止攻击与伤害。

## 星石与周任务

只有自然到时结算星石、历史纪录和本周最好成绩。主动退出不结算这些奖励，已完成加载的挑战次数保留。结算奖励按本局总击杀数逐段累加：

| 击杀范围 | 每次击杀星石 |
| --- | ---: |
| 1–10 | 25 |
| 11–20 | 20 |
| 21–30 | 10 |
| 31及以上 | 5 |

例如击杀10/20/30/31次分别获得250/450/550/555星石。零击杀奖励为0。

| 周任务 | 星石 |
| --- | ---: |
| 完成进入1次 | 300 |
| 完成进入4次 | 500 |
| 完成进入7次 | 800 |
| 本周最好击杀1次 | 200 |
| 本周最好击杀5次 | 300 |
| 本周最好击杀10次 | 400 |
| 本周最好击杀20次 | 500 |
| 本周最好击杀30次 | 600 |

8项任务合计3600星石，分别保存完成与领取标志，单项和全部领取都不会重复支付。任务只依赖Raid次数和最好成绩，不依赖尚未实现的外围任务系统。原版额外任务券属于付费分支，本项目没有免费补领该分支的入口或奖励。

跨周局不会中断：本局突袭首领和入场周固定，自然结束仍发星石并更新对应枪种的历史纪录；即使在加载期间换周，也不把旧周入场或成绩写进新周次数、最好成绩和任务。换周时重置当前周状态，已领取星石与各突袭首领历史纪录保留。每日刷新同样不重启当前战斗。

## 存档与事务边界

沿用 v3 key及武器钱包，在原经济存档中增加可选 `raid` 块：

| 字段 | 含义 |
| --- | --- |
| `entryDay`、`freeUsed`、`adUsed` | 本地日索引及当日入场使用状态 |
| `seasonIndex`、`seasonTryCount`、`seasonBestLevel` | 当前周及其挑战次数、最好击杀数 |
| `bestByType` | 按7种武器类型顺序保存历史最好击杀数 |
| `missionClear`、`missionClaimed` | 8项任务完成与领取标志 |
| `lastSeenMs` | 防时钟回拨的已观察时间 |

缺少或损坏的Raid块独立回退，不清空金币、武器、关卡、转生或普通挑战。选枪、临时战斗、突袭首领生命、加载与广告token不持久化；重载进入主线，只恢复已提交的次数与奖励。转生不清Raid进度。免费扣次、广告成功入场、自然结算、任务领取都通过 `BattleSession` 的批量变更保存，避免钱包和任务标志分开提交。

`RaidBossCombat`仅持有当前突袭首领的生命和层数，同一对象由 `RaidSystem` 和 `CombatWorld` 共享。世界负责同步命中，session负责时钟和经济，HUD只读取快照与调用命令。通过全局 `roundId` 拒绝旧模式的帧和结算事件。
