# Forest Gunner

参考 Cat Gunner 的竖屏微信小游戏原型，使用 **Cocos Creator 3.8.8**。主线按原版每关五波自动推进，第五波包含 Boss，超时后自动重试；地图外观每十关循环，生命和金币数值继续增长，没有设计上的最终关。支持 1–3 只猫、七类共 65 把武器，以及背包、合成、金币升级、装备位升星、转生和永久强化。普通挑战60秒内清场，首关60钻、每提高一关增加6钻；Raid（突袭）通过60秒突袭首领战及周任务获得星石。广告默认全部关闭，移除PlusPack与扫荡。角色保留原版猫的12张部件、尺寸、骨骼和行走动画，并配套拉弓、弩复位、出拳、施法、挥扇、火铳后坐、火炮后坐七类新武器动作；十套地图、树木、头像及现金掉落美术均恢复原版，头像文件名为 `hud/cat_icon.png`。

原版的 Raid（突袭）和 Boss（BOSS玩法）是两个独立模块，分别对应 `BattleMode` 的 `Raid` 与 `Boss`，当前均已接入。独立 Boss 为无限次的60秒单首领挑战，首关胜利300钻，每提高一关增加30钻；主线 Boss 和突袭首领仍指各自玩法内的敌人。详见 [BOSS说明](docs/BOSS说明.md)。

## 后台资源与界面准备

资源管理使用统一模块声明和共享准备任务。读取存档并完成离线结算后，在核心战场加载期间提前下载前两个必需面板；核心完成后依次准备已解锁的装备、挑战、设置及其他已解锁主面板，全部可操作才进入战斗。当前面板资源就绪后，提前解析紧接的一个面板资源，界面仍逐个创建，下载和解析完成均不能代替界面就绪。未解锁的装备和挑战跳过启动加载，进入游戏后后台优先装备、其次挑战，解锁规则不变。首次 10 秒、再次 3 秒仅为性能目标，不再超时放行。启动继续提前下载后面两个必需面板：资源批量加载最多 4 项并发，预下载队列最多 2 项，微信引擎下载采用原有 6 并发/每帧 6 请求上限。界面创建使用启动专属每帧约 12ms、最多 1024 步预算；进入游戏后恢复点击准备 6ms、后台准备 1ms。失败留在启动页并提供重试，已完成面板继续复用。共享字体与图片包仅在使用方完全相同且满足体积预算时合并。

运行阶段先准备临近解锁面板，再后台准备图鉴；临近条件为入口已显示但仍锁定，转生/皮肤/签到也会在教程完成且只差一次挑战胜利时随进入挑战提前准备。后台界面沿用每帧约 1ms 和防饥饿推进。图鉴保留五列和原滚动手感，使用可见卡片池；背包无需等待图鉴。装备和挑战常驻。关闭页面停止无用刷新，内存警告可回收低频内容和隐藏面板，之后按需重建。资源已取得、已解析、界面可操作和持久缓存是不同状态，正式包通过 `__forestGunnerLoading.snapshot()` 观察。

启动元数据、功能与共享资源按实际依赖拆分；字体按实际字号缩减纹理，完全重复的图片/音频安全去重，处理先于 Creator 哈希生成。未变化资源保持 URL，代码更新不会清空缓存。字体理论 RGBA 展开内存下降不等于 PNG 下载字节同比下降，实际流量按相同游玩路径验收。

详见 [资源加载管理说明](docs/资源加载管理说明.md)。10 秒 / 3 秒和已就绪面板 200ms 是验收目标；本地测试、构建及桌面浏览器检查不能代替微信真机结果。旧交付包和改动前源快照保留用于回退。

## 打开与试玩

运行 `node tools/optimize-resource-data.cjs --check` 可只读检查重新导出是否带回冗余内容；需要清理时使用 `--write --backup <项目外新的绝对目录>`，先备份并校验再写入。此次完整受影响文件备份在 `../AI-Workspace/Work/v1/font-json-optimization-20261016/before`。菜单入口生成器会同步保留精简结果；源字体重新生成后应重新执行检查和 `npm run check`。

需要 Node.js 20 或以上版本和 Cocos Creator 3.8.8。用 Creator 打开本目录，等待资源导入完成，主场景为 `assets/scenes/main.scene`。

双击 `启动试玩.cmd` 会先构建 Web，再打开竖屏试玩页 [http://127.0.0.1:7457/play](http://127.0.0.1:7457/play)。`/` 是游戏入口，`/play` 用竖屏 iframe 展示该入口。服务窗口需保持运行，按 `Ctrl+C` 停止；修改源码或美术后需重新构建。

也可在本目录运行：

```powershell
# 构建测试环境 Web 并启动试玩
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\build.ps1 -Platform web -Environment test

# 顺序构建 Web 和微信；未指定环境时默认 production
```

## 战斗武器尺寸

2026-10-16 武器图片压缩：当前 65 张运行 PNG 合计 **1,816,960 字节（1.82 MB）**，由 8,819,112 字节减少 79.4%。画布长边统一 208 像素（主体最多 204，四边至少 2 像素透明留白），采用 Lanczos 缩图和 RGBA PNG 优化，不进行调色板减色。武器造型、战斗尺寸目标、握点挂接、出弹位置、弓弦世界宽度与动作距离保持；轮廓另一轴的取整差异低于 2%。高清原图和压缩记录见 [压缩目录](../AI-Workspace/Work/v1/weapon-image-compression-20261016/report.json)。本次修改不代表已上传的微信 0.1.22 已更新。

`tools/weapon-battle-size-policy.json` 固定保存七类武器已确认的最低阶基准。每升一阶增加基准尺寸的 3%，同类同阶采用相同目标；弓、法杖、扇子按可见高度，弩、手铳、火炮按可见长度，拳套按可见包围盒面积的平方根衡量。测量忽略透明度低于 16 的像素，等比缩放保留原握点、翻转和弩的既有长宽比例。

修改规则或替换武器图片后，运行 `npm run weapons:sizes:sync` 重新生成战斗缩放，再运行 `npm run weapons:sizes:check` 检查。生成工具使用固定基准计算绝对尺寸，重复运行不会累计放大；基准图片或注册尺寸改变时会要求重新核对基准。构建脚本只检查规则，不自动改写尺寸；图鉴界面继续使用独立的显示配置。

所有非战斗武器界面统一参考普通装备栏的七类尺寸比例，图鉴不再每阶增加 3%。共享基准沿用 `tools/weapon-collection-size-baselines.json`，其中 `gradeProgression: false` 禁止界面品阶增长；战斗规则保持独立。

图鉴与普通／突袭装备位采用 100% 基准，背包、新装备获得弹窗和突袭候选武器采用 75%，详情弹窗采用 120%。这些是各显示区域内部的整体适配系数，同一界面不再为不同类别另定大小；卡片与屏幕整体缩放保持原布局。法杖预览统一右倾 45°，其他类别保留各区域原角度。详情和突袭也通过共用函数应用尺寸，图片及阴影同步，点击区域不变。

图鉴仍按五列排列，卡片和行距保持 240 高、滚动内容高度 3160。`tools/weapon-inventory-size-layout.json` 保存六种动态显示区域的统一系数；`inventoryWeaponDisplays` 保留历史字段名，现同时用于武器界面和突袭。调整基准后运行 `npm run weapons:collection-sizes:sync` 与 `npm run weapons:inventory-sizes:sync`，再运行对应 `:check`；构建前也会检查，重复同步不会累计缩放。详见 [武器尺寸说明](docs/武器系统与特效说明.md)。


背包中全部武器图像及阴影统一向右移动 20，类别文字向下移动 12，为长品阶标记和扇子边缘留出空隙。位置保存在原 UI 节点配置中，格子大小和拖拽区域保持原值。

维护时保留以下行为：

- 核心战斗与 Creator 解耦，逻辑坐标保留原版 Unity XZ 地面语义；保持索敌优先级、独立物理步、画面帧更新和随机调用顺序。
- 每次成功购买攻击力、攻速或金币升级，都应刷新全部活动猫并清零当前散布，即使攻速已到下限；保留累计攻击计时，已发射子弹保留发射时的伤害。失败购买不触发刷新。
- 所有背包和武器广告奖励修改统一经过 `WeaponInventory` 事务；动画或回调不能自行改余额、提前发奖或重复发奖。
- 皮肤所有权与选中外观由 `SkinSystem` 持有，经 `BattleSession` 提交和保存。购买使全部持有加成立即生效并刷新散布，装备只热换身体部件和持握手颜色，保留动画、后坐力、脸、描边、武器及在途弹丸。
- 换装、卸装、装备交换及升星成功均刷新活动角色并清零散射，包括同枪交换或空装备槽升星；保留冷却和在途弹丸。纯货币/锁定变化及失败事务不强制刷新。
- 金币钱包与紫币使用 `OriginalInfVal`；金币v3存档保存可选精度，旧档无精度时保留完整原余额。只有显式测试补给使用全升级预算所需的特殊精度。
- 转生与永久强化由 `RebirthSystem` 持有状态，经 `BattleSession` 提交和保存；紫色货币使用独立 `OriginalInfVal` 保留原版截断精度。新系统需要转生重置时加入明确的重置参与项；任务等通知使用保存后的 `onRebirthCompleted`，不能从 UI 直接清存档。
- 旅行和能力由 `AdventureSystem`、`RelicSystem` 计算候选，经 `BattleSession` 整档写入并回读后提交；派遣引用是宠物锁的唯一存档依据。旧 v3 缺块兼容，坏块隔离保留；核心、碎片、收益与成长表统一由 `EconomyConfig` 管理。
- 关卡计时与推进由 `StageProgression` 统一持有；战斗事件必须携带所属 `roundId` 交给会话结算，不能让旧波次事件影响新一波。生命、伤害和金币全程保留大数，只有展示比例转为普通数字。
- 自动合成的候选选择和配对校验统一由 `WeaponInventory` 提供；查询不消耗随机数、不写存档，`WeaponHud` 只管理交互与动画时机。提交时仍校验动画开始时的槽位和枪号，无关抽枪不重新选对。
- `ArtLibrary` 持有统一的 `GameResourceLoader`，初始加载、首次使用与 `GameResourcePreloader` 后台准备共用资源请求入口；`ResourceLoadingPolicy` 集中并发、重试与分帧预算。仅下载和实际加载分别按资源类型与路径合并请求；常用三面板与当前必要弹窗逐项解析后，再交给 `UiPreparationQueue` 分帧构造、布局和提交。非常用面板不因解锁而自动创建，图鉴点击才建，下一关也通过同一后台许可队列；不能把下载完成当作完整界面就绪。
- 共享 SpriteFrame/纹理由资源缓存管理，销毁单个视图不销毁它们；线性弹窗合成的全屏 RenderTexture 和对应 SpriteFrame 按主相机共享，释放单个面板不影响其他占用者，场景结束统一清理。面板自身材质、节点与其他实例独有资源仍由创建者释放。
- 异步加载、组件重复挂载、组件先销毁和父节点销毁都要处理事件、资源与调试接口清理。高频动画和粒子更新复用缓冲。
- `build`、`library`、`temp` 是生成目录，不是源码修改入口；不要修改相邻 `CatGunner-Original` 中的原版证据来适配实现。
